# BGi Desktop：任務派遣確認與角色配置規格

> 日期：2026-08-10（Asia/Taipei）
> 狀態：獨立文字暫代 UI 規格。
> 依據：底部 UI 資訊架構、任務生命週期狀態所有權、完整一輪資料契約與文字暫代 UI 狀態規格。
> 非範圍：不改主規格、Godot 或素材；任務最低／最多人數、非新手時長、報酬、機率與倍率公式均為 `[PLACEHOLDER]`，除已核准的新手固定時長外不自行定值。

## 1. 入口與責任邊界

- 任務派遣的唯一操作入口是同一 BGi 主視窗內的「任務」in-app panel。角色主入口只能查看人物狀態與所屬任務，不能直接派遣、取消或釋放人物。
- 任務卡選取後，在任務 panel 展開派遣確認卡；其可拖曳至桌面可用區任一位置，具有可見關閉操作，且不以額外 Windows native child window 呈現。
- 一次只可展開一張派遣確認卡。若存在 `completed_pending_claim`，收取卡優先於新的派遣確認。
- 已確認派遣後，唯一權威資料是已保存 `MissionRunRecord` 與 `crew_by_id`；派遣確認卡只顯示其衍生狀態。

## 2. 任務卡資訊結構

| 區塊 | 必顯示欄位 | 文字暫代規則 | 操作 |
| --- | --- | --- | --- |
| 摘要列 | 任務 ID、目前狀態、時長。 | 新手任務顯示已核准時長；後續任務時長未定時顯示 `[PLACEHOLDER]`。 | 選取可用任務；其他狀態只查看。 |
| 派遣條件 | `min_assignees`、`max_assignees`、全域並行限制提示。 | 未定人數顯示 `[PLACEHOLDER]`；全域上限目前為 0 時顯示「未限制」。 | 開啟派遣確認。 |
| 報酬揭露 | 保底報酬、額外報酬範圍、額外機率、團隊倍率說明。 | 所有未定內容保留 `[PLACEHOLDER]`；欄位不得隱藏。 | 展開／收合詳細說明。 |
| 派遣中 | 指派人物、預計完成時間、剩餘時間。 | 倒數由 `due_at_seconds` 衍生；不得由 UI 自行遞減權威資料。 | 查看任務，不提供取消。 |
| 完成待收取 | 固定保底、固定額外結果、`result_id` 的可追溯顯示。 | 額外為 0 顯示「未取得額外獎勵」。 | 收取成果。 |

## 3. 派遣確認卡與角色配置

### 3.1 可選角色清單

| 角色狀態 | 清單呈現 | 可選取 | 說明 |
| --- | --- | --- | --- |
| 已解鎖且可用 | 人物 ID、可用標籤、選取方塊。 | 是。 | 初始 5 名為彼此獨立的 roster Unit，皆參照 `character.worker01`；`starter_18 → territory_02` 成功收取後新增 1 名同 Type 的獨立 Unit。 |
| 已解鎖但派遣中 | 人物 ID、派遣中標籤、所屬任務 ID。 | 否。 | 顯示 `ui.dispatch.error.crew_busy` 的原因文字。 |
| 已解鎖且原任務已完成待收取 | 人物 ID、可用標籤與待收取任務 ID。 | 是。 | 完成交易已安全保存後恢復可用；可參與其他任務，但待收取成果尚未入帳。 |
| 未解鎖 | 鎖定人物 ID／名稱、解鎖條件。 | 否。 | 條件未定時顯示 `[PLACEHOLDER]`。 |

### 3.2 確認卡固定欄位

| 欄位 | 規格 |
| --- | --- |
| 任務摘要 | 任務 ID、時長、保底、額外範圍／機率與目前任務狀態。 |
| 人手計數 | `已選 {selected_count} / 最少 {min_assignees} / 最多 {max_assignees}`。 |
| 已選角色 | 以人物 ID 顯示已選順序；同一人物不可重複出現。 |
| 團隊倍率 | `crew_reward_multiplier` 必須在確認前明示；實際公式與數值為 `[PLACEHOLDER]`。 |
| 主要動作 | `ui.action.dispatch`＝「確認派遣」；只有所有前置通過時啟用。 |
| 次要動作 | `ui.action.close`＝「返回任務列表」；只關閉確認卡，不改寫選取以外的任務資料。 |
| 錯誤列 | 顯示一個目前阻擋原因與對應 `error_code`；不以顏色作唯一提示。 |

## 4. 操作流程與文字鍵

| 步驟 | 玩家動作 | 前置／驗證 | 成功結果 | 拒絕或阻擋文字鍵 |
| ---: | --- | --- | --- | --- |
| 1 | 選取 `available` 任務。 | `MissionBoardEntry.board_state=available`。 | 展開派遣確認卡。 | 已接受／已收取任務僅顯示 `ui.action.view_details`。 |
| 2 | 選取或取消選取可用人物。 | 人物已解鎖、可用且未重複。 | 更新已選人數與明示團隊倍率。 | `ui.dispatch.error.crew_busy`、`ui.dispatch.error.crew_duplicate`、`ui.locked.requirement`。 |
| 3 | 按「確認派遣」。 | 人數位於最低／最多邊界；全域限制未達；存檔可寫入。 | 建立並保存 `MissionRunRecord`，任務進入 `active`，人物改為派遣中。 | `ui.dispatch.error.crew_count_below_min`、`ui.dispatch.error.crew_count_above_max`、`ui.dispatch.error.global_cap_reached`、`ui.save.load_error.title`。 |
| 4 | 查看派遣中任務。 | `run_state=active`。 | 顯示 `ui.mission.active.title`、`ui.mission.remaining_time` 與隊伍。 | 不提供收取、刷新替換、重派或取消。 |
| 5 | 任務到期。 | `now_seconds >= due_at_seconds`。 | 先固定並保存結果、`completed_pending_claim` 與原派遣人物恢復可用狀態。 | 未保存前只顯示處理中，不顯示收取按鈕或人物可用。 |
| 6 | 查看已完成待收取。 | 已保存 `result_snapshot`。 | 顯示 `ui.mission.claimable.title` 與收取動作；原派遣人物可參與其他任務。 | 不提供同一任務重派、刷新替換、重骰或取消。 |

## 5. 不可取消提示與收取關係

- 派遣中與完成待收取任務不顯示取消按鈕。
- 若舊 UI、快捷鍵或不合法呼叫送出取消請求，回傳 `mission_cancel_not_supported` 與：
  - `ui.mission.cancel_unavailable.title`＝「目前無法取消」
  - `ui.mission.cancel_unavailable.body`＝「已派遣任務將持續至完成。完成後可收取成果。」
- 此拒絕不得改變人物狀態、任務時計、固定結果或收取資格。
- 人物只在完成交易已安全保存固定結果、`completed_pending_claim` 與可用狀態後釋放；完成待收取不等於成果已入帳。收取失敗不得將人物回退為派遣中。

## 6. 與全域 panel 優先序的整合

| 全域 UI 優先層 | 派遣配置規則 |
| --- | --- |
| H1-0：存檔錯誤／`recovery_hold` | 不開啟派遣確認、不接受選人；保留唯讀任務細節與重試讀取。 |
| H1-1：完成待收取 | 收取卡優先。已有派遣確認卡時，保留選取但收合；收取完成後玩家可重新開啟確認。 |
| H1-2：派遣確認 | 確認卡只在任務 panel 開啟；角色 panel 可查看，不能與其競爭選人狀態。 |
| H2-1：派遣中 | 顯示倒數與隊伍；角色入口以角標同步忙碌數。 |
| H2-2：刷新額度 | 不得在確認派遣、派遣中或待收取任務上套用刷新。 |

## 7. 無美術驗收

1. 新存檔顯示 5 名外觀相同、可獨立選取的初始 roster Unit；它們皆參照 `character.worker01`。任務確認卡明示最低／最多人數與團隊倍率欄位，即使內容為 `[PLACEHOLDER]`。
2. 可選取多名人物；選取忙碌、未解鎖或重複人物時顯示對應文字鍵，且未改變任務或人物資料。
3. 確認派遣後，任務卡顯示派遣中、剩餘時間與隊伍；角色入口同步顯示忙碌數。
4. 對派遣中任務送出取消請求，收到不可取消文案，隊伍與倒數不變。
5. 到期後必先看到固定結果的可收取卡；原派遣人物恢復可選，可參與其他任務。成功收取後才套用成果與長期進度；收取失敗時人物仍可選。`starter_18 → territory_02` 首次成功收取後，roster 增加 1 名可獨立派遣的 Unit，且其 Type 為 `character.worker01`。
6. 在緊湊配置下，收取卡優先於派遣確認卡；兩者維持同一主視窗內的 z-order，且可見關閉操作與 `ESC` 行為符合全域 panel 規則。
