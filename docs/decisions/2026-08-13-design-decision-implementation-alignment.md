# 設計決策與實作對照（2026-08-13）

> 狀態：盤點基線；不新增或覆寫產品決策。
> 範圍：比對 2026-08-10 已核准規格、其補充文件，以及目前 Godot 新手／任務流程。
> 非範圍：本文件不授權修改 Godot、素材、既有規格或歷史文件。

## 背景

目前程式已具備任務接受、離線到期判定、結果鎖定、領取與部份復原的元件級原型；尚未形成可保存、可重入且可完整跑完的新手循環。本對照將已核准規則分成已落地、刻意保留的數值空缺，以及需要優先修正的衝突。

## 決策

後續實作以「任務執行個案（MissionRun）與已保存收據」作為完整循環的基準，而非以任務定義 ID 或暫存記憶體作為唯一狀態。人物在完成交易安全保存後恢復可用；新手進度與首次地盤觸及只可在領取交易成功後提交。

此決策只整理既有核准內容，正式規則仍以[主規格](../superpowers/specs/2026-08-10-bgi-desktop-territory-exploration-design.md)及其獨立補充文件為準。

## 刻意保留的數值空缺

下列項目為策劃待定，並非實作缺陷；未經遊玩測試不得自行填值：

- 任務的保底、額外獎勵上限 N、額外獎勵機率與多人報酬倍率。
- 教學結束後的 15 分鐘 N、1 小時 X、2 小時 Y 任務數量與任務池權重。
- 各地盤解鎖門檻、探索收藏產出、環境布置效果與時鐘異常容忍上限。
- Steam Cloud 接入時機與跨裝置衝突處理；第一版仍以本機存檔為唯一權威。

## 優先衝突與缺口

### P0：教學任務被刷新替換

目前新手面板的刷新路徑會更換目前任務，與「固定 T01–T23、未接受教學任務不可刷新替換」直接衝突。此問題先於任何任務池隨機化處理。

### P0：教學在到期時提前推進

教學完成協調器在任務到期後即推進下一步，與「完成待領取」及「領取成功後才推進」直接衝突；中斷復原也因此不能可靠判定玩家應回到哪一個畫面。

### P0：結果與收據未持久化

任務結果和已領取紀錄仍以 task_id 與記憶體資料為主，且執行快照未涵蓋已固定結果／收據。相同任務定義日後可重複出現，故不可作為領取冪等鍵。

### P0：人物沒有完成待領取狀態

人物狀態更新目前不能寫入 COMPLETED；若以「仍派遣中」替代，UI 與選人規則無法明示任務已完成但尚未領取。

### P1：地盤解鎖未綁定領取交易

目前可由獨立操作直接觸及地盤，且沒有新增完整人物資料。這會繞過報酬、收據與復原保護。

### P1：存檔失敗仍顯示領取成功

demo 在領取後的快照清除失敗時仍呈現成功結果；正式流程必須保留可重試的待領取狀態，直到收據與效果提交成功。

### P1：新手 checkpoint 與玩家行為 log 未接線

教學順序及事件欄位尚未持久化，無法滿足中斷續玩與後續行為追蹤要求。

## 實作順序與驗收邊界

1. 先修正教學刷新與「到期不推進」兩項 P0 行為，且以文字暫代操作驗證。
2. 再建立 mission_run_id、固定結果與 ClaimReceipt 的本機持久交易；驗證重啟與重複領取。
3. 將人物完成待領取、教學 checkpoint、地盤首次觸及與事件 log 接到同一筆成功領取交易。
4. 最後把已穩定的循環接至底部桌面 UI；無美術流程必須可手動操作與 headless 自檢。

在第 1 至 3 項完成前，不得宣稱「完整一輪遊玩」已可驗收，也不應建立 BGi-desktop_QA 作為通過里程碑。
