# BGi Desktop：地盤＋探索放置遊戲設計規格

> 狀態：已核准的策劃方向；數值均為 `[PLACEHOLDER]`，須經遊玩測試後才能定案。
>
> 範圍：本機買斷桌面版的遊戲設計。本文不包含 Godot 實作設計。

## 1. 產品定位與邊界

玩家扮演一位想成為「黑社會老大中的老大」的新人。玩家由 5 名外觀相同、最低階層的小弟起步，透過派遣、探索採集、取得收藏與擴張虛構世界中的地盤，逐步提高勢力。

所有勢力、地區、權貴、任務與收藏均屬虛構。勒索、敲詐、脅迫、仗義行俠僅為任務敘事包裝，不對應真實人物、組織、交易或可執行方法。美金、USDT、歐元、台幣、人民幣、日圓等僅為遊戲內的報酬分級標籤；不可兌換、提領、交易或按現實匯率換算。

本版排除 GPS、真實世界移動、地點資料、行動端專屬功能、雲端帳號與付費內容。外觀 DLC 與新角色可在後續另立規格，本機買斷版不依賴它們。

## 2. 設計支柱

1. **看得見的勢力成長**：每次派遣與收取都應累積成可見的地盤、收藏或場景變化。
2. **低頻但有判斷的桌面互動**：一次開啟應能在 1–3 分鐘內完成收取、派遣與查看；選擇派誰、何時保留人手、何時刷新任務必須有意義。
3. **沒有空手而回的隨機性**：所有任務都有保底報酬；隨機部分只影響額外報酬，並對玩家明示範圍與機率。
4. **探索採集驅動後期**：高階內容以探索、採集與稀有收藏為主；地盤是解鎖條件與長期目標，不是高壓競爭系統。

## 3. 核心循環

### 即時循環（數秒）

玩家查看小弟狀態與任務卡，選擇是否派遣。任務卡立即顯示條件、時長、保底報酬、額外報酬範圍與機率。確認後，小弟進入派遣中狀態。

### 單次開啟循環（1–3 分鐘）

1. 收取已完成任務的保底與額外報酬。
2. 檢視可占據或可強化的地盤，以及缺少的影響力或收藏。
3. 派遣可用小弟，或在有刷新額度時替換未接受的任務。
4. 視需要布置已取得的收藏或環境物件，獲得小幅效果與場景回饋。

### 長期循環（數天至數週）

任務報酬 → 首次觸及新地盤並解鎖人物 → 提升影響力與收集收藏 → 占據／強化地盤 → 解鎖更高階探索採集任務與收藏套組 → 擴張勢力可見範圍。

## 4. 小弟與派遣規則

### 初始狀態

- 初始 roster：5 名彼此獨立、可持久化且可派遣的 Unit；全數參照同一 Character Type `character.worker01`。
- 外觀：完全相同的最低階層人物；本機買斷第一版不使用外觀特化。
- 初始能力：統一的基礎派遣容量 1；每人可單獨執行 1 個任務。

### 人物解鎖

- 首次觸及每個新地盤區域時，新增 1 名獨立、可持久化且可派遣的 roster Unit 並加入可派遣名單；不須等待該地盤完全占據。此批已核准的 `starter_18 → territory_02` 所新增 Unit 亦參照 `character.worker01`。
- 人物解鎖是地盤擴張的本機遊戲進度，不是付費內容。
- 新人物在第一版的主要價值是增加可用人手與任務選擇，並與所屬地盤建立敘事連結；其基礎派遣容量同樣為 1。個別能力、外觀與成長差異不在本規格定案，後續若加入須另立角色規格。

### 派遣規則

- 每名小弟同時只能參與 1 個任務。
- 每個任務可設定最低派遣人數 `min_assignees` 與最多派遣人數 `max_assignees`。玩家可派遣最低人數以滿足任務需求，也可在上限內追加人物。
- 追加人物可依該任務預先設定的 `crew_reward_multiplier` 提高報酬倍率；倍率上限、每增加 1 人的增量與適用報酬類型均為任務資料，必須在任務卡上明示。
- 每名已派遣人物都會在任務期間不可用；同一人物不可重複填入同一任務。
- 保留全隊同時任務上限參數 `global_concurrent_mission_cap`；初值為 `0`，意為無全隊上限。此參數僅作日後平衡調整，不在第一版形成額外限制。
- 任務使用即時倒數；應用程式關閉期間持續計時，重新開啟後結算。
- 派遣中小弟不可接其他任務；完成並收取後恢復可用。

### 後續成長原則

第一版不將人物拆成複雜職業樹。新增人物的能力、外觀與成長差異若要進入玩法，必須先定義其對任務資格、額外報酬與視覺表現的完整關係，避免只增加無用途的角色數量。

## 5. 任務系統

### 任務池

- 任務由系統主動提供，玩家決定是否派遣；任務不會因時間逾期自動消失。
- 每 6 小時提供 1 次手動刷新額度，最多累積 1 次。
- 刷新只替換尚未接受的任務；已派遣任務不受影響。

### 新手固定任務組

新手期必須先提供下列固定任務組，共 23 個任務；目的在於以秒級回饋教會玩家派遣、收取、多人派遣與報酬倍率。此任務組的時長與數量不是 `[PLACEHOLDER]`，不得由隨機任務池取代。

| 任務時長 | 任務數量 |
| --- | ---: |
| 5 秒 | 2 |
| 10 秒 | 3 |
| 30 秒 | 4 |
| 1 分鐘 | 2 |
| 3 分鐘 | 4 |
| 10 分鐘 | 5 |
| 15 分鐘 | 3 |

新手固定任務在未接受前不因手動刷新而消失。此組任務的具體敘事、報酬、最低人數與團隊倍率可配置，但必須維持上述時長與數量。

### 新手固定順序與不中斷復原

- 新手任務依時長由短至長固定排序為 `T01`–`T23`：5 秒×2、10 秒×3、30 秒×4、1 分鐘×2、3 分鐘×4、10 分鐘×5、15 分鐘×3。任務內容可調整，但不得改變此順序、時長或數量而未更新規格。
- 教學完成前，啟動或重啟程式必須自動恢復教學流程；一般任務與手動刷新不得取代、跳過或重排教學任務。
- 每次教學任務開始、完成、結果固定與收取後，必須保存目前任務、最後已確認步驟、結果識別與收取狀態。已結算報酬須以結果識別去重，不得因復原而重複給獎。
- 復原優先序為：有效的進行中任務 → 已完成但未收取的固定結果 → 最後已確認步驟的下一步 → 最近可辨識的前一步任務 → `T01`。資料損毀或閃退時，回退只能重建任務狀態，不得新增或扣除報酬。
- 教學完成的判定為 `T01`–`T23` 均已完成並收取；完成前不得進入可替代教學流程的一般任務池。

### 區域常規任務時長

- 完成新手固定任務組後，常規任務池以 15 分鐘 `N` 個、1 小時 `X` 個、2 小時 `Y` 個的配置方式產生；N、X、Y 為 `[PLACEHOLDER]`，由後續調校表定義。
- 第一個地盤區域不得出現超過 2 小時的任務。
- 超過 2 小時的任務僅能在後續地盤區域解鎖後出現，且必須先通過任務時長與離線結算的遊玩測試。

### 任務類型

| 類型 | 敘事包裝 | 主要產出 | 玩家判斷 |
| --- | --- | --- | --- |
| 勢力任務 | 勒索、敲詐、脅迫、仗義行俠等虛構事件 | 影響力、一般分級貨幣標籤報酬 | 是否投入可用人手以換取地盤進度 |
| 探索採集 | 探索未知地區、搜尋藏寶點、採集稀有物 | 收藏、材料、高階分級貨幣標籤報酬 | 是否為長時任務保留小弟 |
| 地盤任務 | 巡查、整頓、建立據點 | 地盤控制進度、環境物件 | 是否優先推進下一個區域 |

### 報酬結算

每張任務卡必須顯示：

- 任務解鎖條件與可派遣人物。
- 最低／最多派遣人數、目前已派遣人數，以及追加人物後的報酬倍率。
- 即時時長與完成時間。
- 保底獎勵。
- 額外獎勵的範圍 `0～N`。
- 每個額外報酬倍率或結果的機率。

不使用「失敗」或「成功率」作為玩家可空手而回的敘述。人物數符合最低需求時任務必定完成，且必給保底獎勵；額外報酬可為 0。當任務設定允許時，保底報酬可依已明示的團隊倍率提高，額外報酬的機率與上限仍以卡面資料為準。高階資源的經濟控制，僅可透過 N、結果分布、任務時長、解鎖門檻與團隊倍率上限調整。

所有機率、N 值、保底量與任務時長都標為 `[PLACEHOLDER]`，須建立調校表並以遊玩資料驗證。不得使用真實貨幣匯率或市場價格作為數值來源。

## 6. 地盤、資源與收藏

### 地盤狀態

每個虛構街區採四段狀態：

1. **未涉足**：僅顯示輪廓與解鎖條件。
2. **已觸及**：完成首次進入該區的任務，立即解鎖 1 名新人物，並開放基礎任務。
3. **施加影響**：已累積部分影響力，解鎖更多該區任務。
4. **已占據**：提供可見場景變化、解鎖高階探索採集任務，並可放置該區環境物件。

初期地盤數量、每區影響力需求、解鎖順序均為 `[PLACEHOLDER]`。地盤不會被其他勢力奪回，以維持低壓放置體驗。

### 地盤受損與修復

- 受損是已擁有地盤上的暫時 condition／事件狀態，不是第五個地盤 progression state；受損不得改變所有權，亦不得使地盤退回前一個 progression state。
- 受損只在後續指定地圖或遊戲進程啟用後才可能發生。玩家離線達到資格後，系統可依週期性隨機檢查產生受損；啟用節點、離線門檻、檢查週期、機率、同時受損數量與程度分級均為 `[PLACEHOLDER]`。
- 受損必須在場景中有清楚可見的毀損效果。受損物件若具有另行已核准的 gameplay ability／effect，該 effect 只在修復完成前暫時失效；受損不得影響地盤所有權、進度、已取得收藏或背景／掛件所有權。
- 玩家點擊場景中的受損位置，開啟修復選單；可選擇支付貨幣立即修復，或派遣符合條件的人物進行需等待完成的修復。價格、人數與時長均為 `[PLACEHOLDER]`。修復派遣使用既有人物可用性與派遣邊界，不建立特殊人物系統。

### 資源分工

| 資源 | 來源 | 用途 | 經濟原則 |
| --- | --- | --- | --- |
| 影響力 | 勢力與地盤任務 | 推進地盤狀態 | 穩定、可預期的核心進度 |
| 分級貨幣標籤報酬 | 各類任務 | 表現報酬等級與解鎖門檻 | 僅為遊戲分類，不可換算或交易 |
| 收藏物 | 探索採集任務為主要來源；可作為任務額外獎勵 | 完成套組、布置場景、解鎖任務 | 稀有度由任務門檻與分布控制；不得推導為所有任務皆直接產出收藏 |
| 資源類／環境材料 | 放置產出與任務產出 | 後續製作、放置或其他已核准用途 | 提供小幅便利，不得取代任務選擇 |

### 布置

布置的首要功能是強化「我占據了這裡」的可見感受。每個物件可提供小幅、可讀的效果，例如某類探索任務額外報酬上限微幅增加 `[PLACEHOLDER]`。同類效果須有上限，避免無限制疊加。

### 收藏展示類型、所有權與第一批方向

收藏展示不再以「可用於背景裝飾／僅 Icon」二分；「背景」只指完整背景。各展示類型如下：

| 類型 | 玩家體驗與已核准規則 |
| --- | --- |
| 完整背景（Full Background） | 替換整體場景背景；沿用背景收藏庫、套用確認與切換規則。 |
| 前景掛件（Foreground Attachment） | 場景覆蓋層；沿用既有自由拖放及位置保存規則。 |
| 場景物件（Scene Prop） | 顯示於場景，但不是自由拖放前景掛件；placement UX 尚待決策。 |
| 場景套件（Scene Set） | 整組場景 Layer；玩家可擁有多套，同一套件類別於同一背景一次只展示一套。切換只改變目前展示，不移除既有所有權。 |
| 純收藏（Pure Collectible） | 僅存在收藏介面／Icon 層，不直接顯示於場景。 |

第一批已確認內容如下：

| 類型 | 內容 |
| --- | --- |
| 前景掛件 | LED 霓虹招牌、懸賞令 |
| 場景物件 | BEMZ 豪華保母車、總部大樓 |
| 場景套件 | 城市建築套組 |
| 純收藏 | 999K 特級金磚、市長的水果禮盒、檳榔西施的寫真 |

- 城市建築套組可包含矮公寓或高樓都市景觀等不同套組。玩家取得後永久保留所有權；套用另一套不刪除原有套組。總部大樓可有多個不同收藏，但同一背景同時只展示一棟。
- **Unique**：單一具名收藏只能取得一次；目前例為特定金磚、寫真、總部大樓與城市建築套組。**Stackable**：同一收藏可累積數量；目前僅確認市長的水果禮盒。**Series**：多件不同收藏屬同一系列、各自具獨立 ID 與所有權；LED、懸賞令與後續多款 BEMZ 原則上採此方式，不預設為同一物品堆疊。
- 收藏採 identity-first 穩定 ID。ID 不得編碼可變的展示能力、所有權或玩法分類；展示以獨立屬性（如 `foreground`、`scene_prop`、`scene_set`、`none`）表示，Unique／Stackable 亦為獨立屬性，Series 為內容關係。命名空間採 `region.r01`、`collectible.r01.<identity>`、`background.r01.<identity>` 與 `resource.<identity>`；不採 `item-region01-1-001`、`item-region01-2-001` 或一般資源 `item-00`。
- Resource 與 Collectible 是不同概念與命名空間。資源可由任務及放置產出；收藏的具體任務、地區、進度、掉落表與機率，以及資源類型、用途、速度、容量和收取規則，均為 `[PLACEHOLDER]`。

### 背景收藏與前景掛件

- 每個地區可在設定的地盤推進獎勵節點解鎖 1 張完整背景布景；第一張背景主題為「高架線與霧金天際線」。背景名稱只定義主題，不包含素材導入或美術授權決定。
- 解鎖背景時，先將其加入背景收藏庫，不得直接替換目前啟用背景。系統對該次解鎖提出一次套用提示與確認視窗：`確認套用` 只更新目前啟用背景；`暫不更換` 保留原背景，並讓新背景留在收藏庫。
- 玩家可在背景收藏庫手動選取任何已擁有背景；每一次實際切換前都必須要求確認。若同時解鎖多張背景，提示須依序排隊，不得遺失已解鎖背景。
- 所有裝飾掛件均為獨立前景／覆蓋層。首次取得時，掛件使用美術指定的預設位置；這個預設只在首次建立掛件狀態時使用。
- 首次取得後，玩家可在主題畫布的可用範圍自由拖放掛件；不採棋盤、格點、背景專屬掛點或自動吸附規則。玩家移動後，保存相對於桌面場景畫布的座標、前景層級與顯示狀態；這些資料不得綁定特定背景。
- 背景替換、動態效果切換、程式重啟、故障復原或靜態備援切換只能改變相關背景或效果狀態，不得重置、移除、隱藏、重新定位或變更任何掛件的所有權。
- 畫布尺寸或桌面配置改變時，只有超出可用範圍的掛件可被夾回最近可見邊界；不得回到美術預設位置、刪除、改變所有權或任意改寫仍在可用範圍內的座標。
- 派遣與地盤佔領維持選單式數值操作；背景收藏庫不是棋盤式地圖，也不承載地盤數值。

### 動態效果相容性

- 完整背景與前景掛件都必須可宣告多個獨立的動態效果插槽。插槽綁定目標層與相對位置，而非綁定單一場景、背景或掛件實例。
- 每個插槽至少保留效果類型、啟用狀態、強度、速度與靜態備援外觀；具體視覺參數、效果清單與美術表現由後續設計定義，不在本規格預先固定。
- 背景可使用插槽呈現大樓呼吸燈、霧金高架線明暗循環等效果；掛件可使用插槽呈現招牌閃爍、收藏物漂浮或局部光源脈動等效果。
- 背景替換時，只替換該背景自身的效果插槽；所有掛件的效果插槽、啟用狀態、參數、位置與前景層級均不得改變。
- 動態效果未配置、未啟用或無法使用時，背景與掛件必須以靜態備援外觀正常顯示。動態效果只服務視覺回饋，不得改變派遣、佔領或報酬數值。

## 7. 桌面體驗

### 桌面常駐型介面

產品應呈現為直接鋪在 Windows 桌面上的遊戲 UI，而非一般應用程式視窗：不使用標題列、外框、最小化／最大化按鈕或拖曳式縮放框。預設位置錨定在螢幕底部、Windows 工作列上方，讓地盤場景橫向延展；參考圖中工作列上方的場景、左右功能區與任務區構成，而不採用圖中的宣傳文字與箭頭。

- UI 以螢幕可用工作區自適應排列；可在設定中切換緊湊／標準配置，但不以可縮放視窗作為互動模型。
- 未繪製遊戲 UI 的區域保持透明且不攔截桌面操作；遊戲控制項才接受點擊。
- 預設只在桌面層顯示，不覆蓋一般工作視窗，避免妨礙正常工作；玩家可從設定啟用或關閉桌面常駐顯示。
- 場景中央呈現目前地盤；左側放置地盤／布置功能區；右側為可收合的任務、收取與刷新區。具體美術尺寸與元件排列於 UI 規格階段定義。
- 背景收藏庫與前景掛件各自提供入口；背景選取後以確認視窗完成切換，掛件可在主題畫布可用範圍自由拖放，且不因背景切換而移動或消失。
- 小弟狀態至少區分可用與派遣中；任務「已完成待收取」必須由任務卡與收取提示清楚呈現，不得把可用人物誤標成仍被任務占用。
- 場景中的受損位置必須可點擊並開啟修復選單；修復選單不得遮擋可收取成果或派遣確認。
- 提示：應用程式內使用角標與任務區提示；桌面系統通知不列為第一版必需功能。
- 目標：即使玩家只看場景，也能知道勢力是否正在運作、地盤是否推進、是否有可收取成果。

## 8. 本機資料、離線結算與例外

- 第一個可遊玩版本以本機存檔為唯一資料來源，不要求帳號或跨裝置同步。
- 正式 Steam 發行版本必須支援 Steam Cloud 存檔；此項整合延後至 Steam 發行工作項，但本機存檔結構須能被雲端同步，不得依賴機器專屬路徑或未可序列化資料。
- 記錄派遣開始時間、預計完成時間、收取狀態與刷新額度的下一次可用時間。
- 記錄背景收藏庫、目前啟用背景、尚未處理的背景提示佇列，以及每個前景掛件的擁有、顯示、層級與相對位置。
- 記錄每個收藏的 identity-first ID、所有權行為與數量（如適用）、Series 關係與展示類型；場景物件與場景套件的所有權及目前啟用套件亦須保存。場景物件的 placement 資料在 UX 定案前不得自行假設。
- 為每個掛件記錄首次美術預設位置、玩家是否已移動、玩家最後保存的相對畫布座標與最近一次邊界夾回資訊；邊界夾回不得覆寫首次預設位置或玩家所有權。
- 記錄背景與掛件動態效果插槽的啟用狀態與設定參數；循環播放相位可在載入時重新計算，不要求持久化。
- 記錄已啟用地盤的受損 condition、受損目標、可見效果狀態與修復中的既有派遣關聯；不得把受損寫成地盤 progression state 或覆寫地盤／收藏／掛件所有權。
- 重啟時依本機時間結算完成任務。對異常大幅時間跳躍採安全上限與清楚提示；上限值為 `[PLACEHOLDER]`，需在測試後定案。
- 任務已完成但尚未收取時，結果必須固定，避免重啟重骰額外報酬。
- 本機資料損毀、時間異常或任務資料不完整時，應保留已確認的保底成果並提示玩家，不得靜默扣除資源。

## 11. 完整一輪遊玩與 QA 建立門檻

### 目的與範圍

完整一輪遊玩是後續里程碑：證明核心放置循環可從新存檔走到地盤推進與人物解鎖，且可在沒有正式美術的條件下被文字暫代操作與 headless 自檢驗證。此門檻不要求中止、重排或阻塞既有 coding 小目標；`BGi-desktop_QA` 僅能在本節全部驗收項通過並留有結果紀錄後建立。

報酬量、額外範圍 N、機率、地盤門檻、人物解鎖門檻與團隊倍率皆為 `[PLACEHOLDER]`。完整一輪必須使用一份有效的測試資料設定，但不得在本規格自行填入上述數值。

### 無美術暫代操作

在正式背景、掛件、人物或動畫素材尚未就緒時，遊戲必須以可視覺化文字暫代介面呈現並操作下列狀態：人物名單與可用狀態、任務卡、任務派遣名單、刷新額度、完成待收取狀態、保底與額外報酬、地盤進度、收藏清單、環境布置清單與新人物解鎖提示。文字暫代是完整一輪的有效驗收面，不得因缺少美術而阻塞。

### 一輪循環驗收情境

| 項目 | 玩家／測試輸入 | 必要輸出與驗收條件 | 邊界與不可接受結果 |
| --- | --- | --- | --- |
| 1. 人物與多人派遣 | 新存檔顯示 5 名相同小弟；選取一張設定最低／最多人數的任務，先滿足最低人數，再在上限內追加人物。 | 每名已派遣人物標記為不可用；任務卡顯示目前人數與團隊倍率。 | 同一人物不得同時進入兩個任務、不得重複填入同一任務；未達最低人數或超過最多人數時，任務不可開始且既有狀態不變。 |

| 6. 可見長期成長 | 收取可推進地盤的有效測試報酬，並完成收藏或布置的有效操作。 | 地盤進度、收藏清單與環境布置清單均發生可見文字狀態變化。 | 任務報酬不得只有不可見數值；布置與收藏不得阻斷地盤或任務主循環。 |

| 8. 新手等待與功能 | 從新存檔依序派遣新手固定任務，至少驗證最短等待任務與一張較長新手任務。 | 新手固定任務組可見，倒數、完成、收取、多人派遣與報酬呈現均可運作。 | 缺少正式美術不得阻塞驗證；不得用跳過等待或直接給獎勵取代倒數狀態機驗證。 |

### Headless 自檢與通過紀錄

- 必須提供可不開啟正式美術畫面的 headless 自檢，使用可控制時間與有效測試資料走完上表 1–8 的狀態轉換。
- 自檢輸出須逐項列示輸入、預期狀態、實際狀態與通過／失敗；任何一項失敗即不具備建立 `BGi-desktop_QA` 的資格。
- 手動文字暫代走查與 headless 自檢必須同時通過。走查紀錄需能對照任務 ID、人物 ID、地盤 ID、結果固定識別與存檔前後狀態，但不記錄或推導新的報酬／機率數值。
- 既有 coding 路線可持續拆分並完成小目標；本節只在核心狀態可串接成完整一輪後作為整合驗收，不作為現行工作中止條件。

### 新手教學玩家行為日誌

玩家行為日誌的目的，是追蹤教學漏斗、派遣挫折、離線復原與報酬呈現是否符合設計。第一階段只記錄本機匿名事件，不上傳玩家行為資料；雲端文件只存事件規格對照表。

- 每筆事件必須含有：`schema_version`、匿名存檔識別、工作階段識別、事件序號、`tutorial_step_id`、任務識別（如適用）、時間資訊、結果與最小必要內容。
- 不得記錄姓名、帳號、IP、真實位置、真實貨幣資料、任意文字輸入或每個倒數 tick／滑鼠移動。
- 日誌寫入失敗不得中斷教學、倒數、結算或存檔；失敗只可產生不含個資的診斷事件。
- 所有事件名稱、欄位與用途以雲端原生表格「BGi Desktop 新手教學玩家行為事件對照表」為準；各事件必須獨立成列，不得合併於同一儲存格。

#### 必要事件目錄

- `tutorial_started`：首次建立或開始教學。
- `tutorial_step_presented`：顯示指定教學步驟。
- `tutorial_checkpoint_saved`：保存可復原教學 checkpoint。
- `tutorial_resumed`：程式重啟後恢復教學。
- `tutorial_checkpoint_restored`：依有效 checkpoint 還原狀態。
- `tutorial_fallback_reissued`：checkpoint 缺失時重建前一步或 `T01`。
- `tutorial_task_card_viewed`：玩家查看教學任務卡。
- `tutorial_task_details_opened`：玩家展開任務細節。
- `tutorial_crew_selection_changed`：玩家調整派遣人數或人選。
- `tutorial_assignment_rejected`：派遣遭拒，原因為人數不足、超過上限、人物忙碌或重複選取。
- `tutorial_assignment_confirmed`：派遣通過，記錄人數與明示團隊倍率。
- `tutorial_task_started`：教學任務開始倒數。
- `tutorial_offline_resume_detected`：重啟後偵測到離線經過時間。
- `tutorial_task_completed`：任務進入完成待收取。
- `tutorial_result_locked`：任務結果與結果識別固定。
- `tutorial_result_viewed`：玩家查看結算。
- `tutorial_reward_claimed`：玩家收取保底與額外報酬。
- `tutorial_zero_bonus_presented`：額外報酬為 0，呈現未取得額外獎勵。
- `tutorial_refresh_attempted`：玩家嘗試於教學期間刷新。
- `tutorial_refresh_blocked`：教學任務不可被刷新替換。
- `tutorial_territory_progressed`：有效教學報酬推進地盤。
- `tutorial_collection_recorded`：收藏清單發生變化。
- `tutorial_decoration_recorded`：環境布置清單發生變化。
- `tutorial_new_character_unlocked`：首次觸及新地盤並解鎖人物。
- `tutorial_state_recovery_failed`：狀態無法完整復原，記錄安全回退原因。
- `tutorial_completed`：`T01`–`T23` 全部完成並收取。

## 12. 規格驗收準則

1. 玩家以 5 名相同小弟開始；每名小弟不可同時參與兩個任務，但一個任務可依最低／最多人數規則派遣多名人物。
2. 任務不逾期；玩家每 6 小時可取得 1 次、最多保留 1 次刷新額度，且刷新只換未接受任務。
3. 關閉應用程式後任務照常完成；結果在完成時固定。
4. 每張任務卡均明示保底報酬、額外範圍與機率；所有完成任務皆提供保底報酬。
5. 額外報酬可為 0，但不以失敗或空手而回呈現。
6. 地盤進度、探索收藏與環境布置形成可見的長期成長。
7. 首次觸及新地盤時解鎖 1 名新人物；此人物屬本機進度，不屬付費內容。
8. 介面以桌面常駐型 UI 顯示於工作列上方，不含一般視窗的標題列、外框或拖曳縮放框，且未繪製 UI 的區域不攔截桌面操作。
9. 第一個可遊玩版本採本機存檔；Steam 正式發行前必須完成 Steam Cloud 同步整合。
10. 地區推進解鎖背景時，背景先收入收藏庫；自動提示與手動切換都必須確認後才變更目前背景。
11. 背景替換不得變更任何前景掛件的所有權、顯示、層級或相對位置；派遣與佔領維持選單式數值操作。
12. 背景與前景掛件均支援獨立動態效果插槽；停用或無法使用動態效果時必須維持靜態正常顯示，且不得影響遊戲數值。
13. 不包含任何真實世界移動、GPS、可交易貨幣或尚未規劃的付費內容。
14. 新手教學以 `T01`–`T23` 固定順序執行；中斷後依復原優先序自動續接，且已結算報酬不得重複給獎。
15. 新手教學行為日誌為本機匿名事件，事件寫入失敗不得阻斷遊戲；每個事件須在雲端原生表格中獨立成列。
16. 掛件首次使用美術預設位置，後續可自由拖放並保存相對畫布座標；背景、效果與故障復原不得覆寫，僅畫布變更時可將超界位置夾回最近可見邊界。
17. 地盤受損是暫時 condition，不改變四段地盤 progression、所有權或既有收藏；玩家可從受損場景位置選擇立即支付或派遣等待修復，具體數值維持 `[PLACEHOLDER]`。
