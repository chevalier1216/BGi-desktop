# SkillsMaintenance Candidate Evidence — 任務目錄與完成狀態可見 UX

狀態：候選證據；僅供後續獨立的 SkillsMaintenance 對話評估，未在本 BGi 任務中修改任何 Global Skill。

## 使用者回報的失敗模式

### 預期

- 任務／收取先開啟任務目錄；使用者選擇一個任務後才開啟該任務詳情。
- 小弟卡片的已選取覆蓋與不可用禁止覆蓋互斥；兩者不可同時顯示。
- 任務計時完成即釋放小弟並讓下一個新手任務可派遣；結果領取是獨立、可稍後完成的動作。
- 玩家不應看到收取紀錄、內部 placeholder 或「完成後才顯示」等開發狀態文字。

### 實際（修正前）

1. 主按鈕直接開啟單一任務詳情，沒有任務目錄，將未來多任務流程誤建模為單一面板。
2. 已選取文字與紅色禁止符號可同時覆蓋同一張小弟卡片。
3. 小弟直到領取固定結果才釋放；完成但尚未領取時會阻斷下一個任務。
4. 收據、固定結果與 placeholder 說明出現在客戶端。

## 最短重現路徑

1. 啟動 BGi，開啟「任務／收取」。
2. 選取小弟並開始 `starter_01`。
3. 等待任務倒數結束，但不點選領取。
4. 檢查小弟可用性、下一個任務與任務介面層級。

修正前可觀察到：小弟仍為不可選、下一個任務未可派遣，且任務詳情混入目錄資訊與內部文字。

| --- | --- | --- | --- |
| 任務入口明確為按鈕，先進任務目錄 | 主入口改為「開啟任務／收取」；目錄分為目前與已完成 | `mission_task_directory_visual_test.gd` | 實際點選與視覺辨識 |

| 選取與禁止覆蓋互斥 | 已選取只在可選人物；不可用只顯示禁止覆蓋 | `desktop_shell_karat_visual_test.gd` | 實際卡片呈現 |
| 計時完成即解鎖小弟與下一任務 | 完成時持久化固定結果、釋放小弟、推進目前新手任務 | 任務流程、保存、全流程、地盤解鎖測試 | 實際倒數與下一任務操作 |
| 結果可稍後領取且收據不外露 | 結果保留可領取；收據與內部 placeholder 不顯示 | claim、保存、全流程測試 | 實際領取視窗與文案 |

`自動化證據` 僅驗證程式狀態與可測視覺結構；不等同使用者已確認互動與畫面完成。

## 可供 Skill 維護評估的抽象問題

1. **流程層級遺失**：單一詳情面板被誤當作可延展的任務系統；visible UX 驗收須先核對目錄、詳情與結果三個層級是否各自可見及可操作。
2. **狀態覆蓋缺少優先權**：同一控制項的可選、已選、不可用狀態必須明定互斥規則並設回歸案例。
3. **交易邊界與 UX 鎖定混淆**：結果持久化／領取的資料完整性，不能自動推導為持續鎖住可重複使用的人物資源。
4. **內部敘述外洩**：placeholder、尚未實作說明、收據歷程與測試性文案須有客戶端文字審核。
