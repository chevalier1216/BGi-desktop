# 文件架構

本目錄保存可被 Git 追蹤、可供產品、設計、程式與 QA 共同引用的專案文件。既有文件位置保持不動；新增文件應先判斷其是否屬於下列類別，再寫入對應位置。

## 文件分類與位置

| 類別 | 位置 | 用途 |
| --- | --- | --- |
| PRD | `docs/prd/` | 產品目標、使用者問題、範圍、非範圍與版本需求。尚未建立 PRD 時，不以聊天紀錄替代。 |
| 正式規格 | `docs/superpowers/specs/` | 已核准且可交給 coding、設計或 QA 執行的需求、資料契約、UI 行為與驗收規則。 |
| 研究 | `docs/superpowers/research/` | 唯讀盤點、可行性、素材／授權、風險與自檢結論；研究本身不代表實作已核准。 |
| 實作計畫 | `docs/superpowers/plans/` | 已核准規格拆出的工作順序、依賴、驗證方式與交付範圍。 |
| Operations | `docs/operations/` | 建置、測試、發行、回復與日常操作手冊。 |
| 決策紀錄 | `docs/decisions/` | 需長期保留的決策、選項、理由、影響與復議條件。 |

目錄尚未存在時，只有在相應文件獲准建立時才建立；不得為整理目的移動、刪除或重建既有文件。

## 正式規格回寫原則

1. 使用者核准的產品或設計變更，必須回寫至適用的正式規格；聊天結論與研究文件不能取代正式規格。
2. 實作、UI、美術或 QA 變更前，先核對現行正式規格；需要改變需求時，先更新規格與驗收條件，再調整後續工作。
3. 研究文件只記錄證據、限制與建議。除非正式規格明確引用並納入，研究結論不自動成為產品需求。
4. 每項可追蹤文件變更都應保留對應調整日誌交接，包含檔案、行號、摘要與驗證結果。

## ChatGPT Project 的角色

ChatGPT Project 只保存討論脈絡、會議式決策過程與指向 Git 文件的連結。可執行的 PRD、規格、研究、操作手冊與決策紀錄以本 `docs/` 目錄中的 Git 文件為準。

## 與跨裝置開發文件的邊界

`CROSS_DEVICE_DEVELOPMENT.md` 屬 coding／開發協作指引，負責跨裝置工作方式、同步與實作環境約定。本 README 不重述其流程；此處只定義可追蹤文件的分類、回寫與引用原則。
